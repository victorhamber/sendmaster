# Memória histórica do projeto

Camada opcional para decisões, descobertas e armadilhas que seriam custosas de redescobrir. Consulte somente quando a tarefa depender de contexto anterior.

- Um arquivo por mês: `YYYY-MM.md`; use a data local do projeto.
- Salve somente o que uma sessão futura teria dificuldade de redescobrir e que evitaria surpresa ou erro real: regra de negócio invisível no código, decisão após tentativas frustradas, ou localização externa importante.
- Não salve fatos deriváveis do código/Git, estado temporário, prazo, raciocínio de rotina ou instrução já registrada em outro documento. Na dúvida, não salve.
- Cada nota deve ser curta: data, assunto, conclusão, evidência/fonte, última verificação e condição que a tornaria obsoleta.
- Não copie conversas, logs completos, segredos ou dados pessoais.
- Não repita o estado atual nem decisões já registradas em `DECISIONS.md`.
- `STATE.md` descreve o presente; esta pasta guarda contexto passado.
- Código e documentação atualizados prevalecem. Confirme notas históricas antes de agir.
- Ao consultar uma nota, valide a evidência e a condição de obsolescência. Corrija ou marque como superada se estiver desatualizada; nunca invente evidência ou data de verificação.

Copie o formato de `_TEMPLATE.md` ao criar a primeira nota mensal.
