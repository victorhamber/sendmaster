# App local
Fontes: `data/`, `src/audience.ts`, `src/campaign-delivery.ts`, `src/campaigns.ts`, `src/forms.ts`, `src/mailer-settings.ts`, `src/mailer.ts`, `src/secret-store.ts`, `src/server.ts`, `src/smtp-transport.ts`, `src/storage.ts`, `src/suppressions.ts`, `app.js`, `campaigns-ui.js`, `providers-ui.js`, `index.html`, `styles.css`, `.impeccable/config.json`, `package.json`, `package-lock.json`, `tsconfig.json`, `AGENTS.md`, `ai-docs/tools/map_repo.py`

- `src/server.ts` serve assets e API same-origin somente em loopback; inclui CRUD de formulários por workspace, página `/forms/:id`, endpoint de inscrições com opt-in simples ou double opt-in, confirmação por POST explícito e tratamento seguro de conexão interrompida.
- `ai-docs/tools/map_repo.py` exclui dados runtime locais do mapa de contexto.
- `src/storage.ts` mantém schema SQLite para tags, vínculos de contato, segmentos e formulários; `src/audience.ts` executa consultas filtradas e operações de audiência; `src/forms.ts` persiste configurações e registra inscrições; `data/sendmaster.sqlite` é criado no primeiro start e ignorado pelo Git.
- `src/campaigns.ts` persiste rascunhos por workspace e retorna o tamanho atual do público confirmado. A UI em `campaigns-ui.js` edita nome, assunto, pré-cabeçalho, HTML e versão texto, com prévia em iframe sandboxed e sem disparo.
- A revisão de campanha permite escolher todos os contatos confirmados ou um segmento salvo; `countEligibleContacts` sempre cruza os filtros com `status='confirmed'`. A fila `campaign_reviews` registra snapshot de público/contagem, mostra também elegíveis atuais e não dispara e-mails.
- `src/suppressions.ts` emite tokens de descadastro com segredo armazenado como SHA-256; GET só mostra a confirmação e POST aplica supressão. Eventos de bounce/complaint por `provider + providerEventId` são idempotentes e atualizam estados pendente/confirmado sem remover supressões existentes. Reativar contato suprimido requer endpoint separado com evidência de novo consentimento. A rota normalizada é local e não pode ser exposta como webhook sem validadores de assinatura por provedor.
- `src/campaign-delivery.ts` prepara envio individual somente para contato `confirmed`, emite link de descadastro por contato com base em `SENDMASTER_PUBLIC_URL`, acrescenta rodapé HTML/texto e chama o adaptador. `src/mailer.ts` mapeia List-Unsubscribe/One-Click para os formatos de cabeçalhos documentados pelos provedores; SMTP inclui os headers MIME. Configuração do endereço público exige HTTPS e domínio acessível por destinatários.
- `app.js` migra/cacheia preferências locais e carrega/persiste contatos pelo workspace ativo, prepara prévia CSV, permite criar/remover tags, aplicar tags a contatos, salvar filtros e construir formulários com tags, prévia e snippet iframe.
- Importações CSV aceitam cabeçalhos email/nome/origem, até 1.000 linhas ou 700 KB; deduplicam por workspace e sempre criam contatos pendentes. A interface mantém contraste de texto suficiente nos rótulos e metadados da interface; tamanho tipográfico original do logotipo preservado e textos funcionais a partir de 11 px. Tags e segmentos pertencem ao workspace; segmentos guardam filtros de busca/status/origem/tag. Atribuições de tag e eventos são persistidos na mesma transação. Contatos têm email normalizado único por workspace, origem, consentimento e status de supressão. Somente `confirmed` com evidência de consentimento representa elegibilidade futura.
- `contact_external_ids` liga o ID canônico do SendMaster a IDs de sistemas externos. `integration_events` registra alterações na mesma transação; ainda não há entrega/retry de webhooks.
- Clientes externos devem falar com a API/eventos, nunca acessar SQLite diretamente. Ainda não há autenticação para uso fora do loopback.
- Ainda sem campanhas reais, integração IA/envio, MCP ou webhooks entregues.
- Campanhas estão em rascunho/revisão local. A tela seleciona segmento e guarda contagem de contatos confirmados, mas não agenda nem envia. O adaptador unitário de entrega é uma seam interna, sem rota/fila de envio. Enquanto o app permanecer no loopback, os links não são públicos e campanhas não devem ser enviadas.
- Cada formulário tem double opt-in ligado por padrão, inclusive em formulários antigos migrados. A checkbox explícita continua obrigatória nos dois modos; double opt-in envia link com token de uso único armazenado como hash, expira em 24 horas e mantém o contato `pending` até uma ação POST explícita. Acesso GET não confirma, para evitar scanners de link. Opt-in simples confirma no cadastro com evidência e horário. O iframe é local e não pode ser embutido em site público antes de hospedagem HTTPS e controles de abuso.
- O catálogo inspirado no plugin lista 13 APIs (SendLayer, SMTP.com, Brevo, Elastic Email, Mailgun, Mailjet, MailerSend, Mandrill, Postmark, Resend, SendGrid, SMTP2GO, SparkPost) e SMTP genérico. `src/mailer.ts` monta payloads por API e `src/smtp-transport.ts` envia com SSL/STARTTLS; `sendWorkspaceEmail` já entrega confirmações do double opt-in. O transporte trabalha com mensagens unitárias, um destinatário por chamada; testes operacionais ficam para o fim, conforme pedido. `src/mailer-settings.ts` protege segredos com DPAPI CurrentUser no Windows ou AES-256-GCM via `SENDMASTER_SECRET_KEY` em servidor; credenciais DPAPI precisam ser reinseridas ao migrar a base para VPS.
- Comandos: `npm run dev`; `npm run typecheck`.
